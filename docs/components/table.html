Table

Table은 어드민 환경에서 데이터를 구조화하여 표시하는 핵심 컴포넌트입니다.
Horizontal Table(목록형)과 Vertical Table(상세형) 두 가지 유형을 제공합니다.

기본 사용법​

import { Table } from '@ncds/ui-admin';

function App() {
  return (
    <Table type="horizontal">
      <Table.Header>
        <Table.Row>
          <Table.HeaderCell>ID</Table.HeaderCell>
          <Table.HeaderCell>이름</Table.HeaderCell>
          <Table.HeaderCell>상태</Table.HeaderCell>
        </Table.Row>
      </Table.Header>
      <Table.Body>
        <Table.Row>
          <Table.Cell>1</Table.Cell>
          <Table.Cell>상품 A</Table.Cell>
          <Table.Cell>판매중</Table.Cell>
        </Table.Row>
      </Table.Body>
    </Table>
  );
}

Row Group (행 묶음)​

체크박스가 있는 상위 행 아래에 체크박스 없는 종속 행이 붙거나, 여러 행을 덮는 병합 셀(rowSpan) 이 있을 때 쓴다. Table.Body 대신 Table.RowGroup 으로 묶으면 묶음 안 어느 행에 마우스를 올려도 묶음 전체와 병합 셀이 함께 hover 되고, 상위 행을 선택하면 종속 행과 병합 셀까지 selected 가 된다.

공급사 A기본 티셔츠 / 화이트 M1₩24,000₩3,000
추가선물 포장1₩2,000
공급사 B캔버스 백 / 베이지2₩38,000무료
추가네임택 각인2₩6,000

묶음당 Table.RowGroup 하나를 쓴다. 선택 상태는 체크박스가 있는 행에만 selected 를 주면 되고, 묶음 전파는 CSS 가 맡는다.

상태판정
묶음 selected묶음 안 Table.Row 중 하나라도 selected
묶음 hover묶음 안 아무 행에나 마우스가 올라감
병합 셀묶음 상태를 그대로 따른다

체크사항​

  • 기본값은 꺼짐이다. Table.RowGroup 을 쓰지 않으면 기존처럼 한 행 단위로만 표시된다.
  • 병합 범위는 묶음과 달라도 된다. 병합 셀의 hover·selected 는 rowspan 이 덮는 실제 범위로 판정한다. 묶음을 쓰지 않는 표에서도 같게 동작하며, 지원 상한은 rowspan 10 이다.
  • 묶음을 가로지르는 병합은 Table.RowGroup 을 쓰지 않는다. rowspan 이 <tbody> 경계를 넘지 못하므로, 선두 칸의 rowSpan 으로 묶음을 만들고 그보다 넓은 병합을 그 위에 얹는다. 아래 중첩 병합 참고.
  • 병합을 덮는 행은 드래그에서 한 덩어리다. 블록 가운데는 드롭 대상에서 빠지고, 겹치는 범위는 모두 합쳐 한 번에 옮긴다. 실제 재정렬은 onRowDrop 을 받은 쪽이 한다.
  • 다른 옵션과 직교한다. 묶음은 스타일 레이어이므로 선택·정렬·헤더 고정·드래그앤드롭 같은 기존 동작은 그대로 유지된다. draggable 표에서는 Table.Body 와 똑같이 onRowDrop 을 넘긴다.
  • 색은 행 단위 hover·selected 와 같은 값이다. 전용 토큰은 없다.

병합 셀 (rowSpan)​

값이 같은 연속 행의 한 칸만 세로로 합치는 경우처럼, 묶음을 쓰지 않아도 병합 셀의 상태는 그대로 전파된다.

방향동작
덮인 행 → 병합 셀범위 안 어느 행이 hover·selected 든 병합 셀도 같은 상태
병합 셀 → 덮인 행병합 셀에 마우스를 올리면 덮인 행이 함께 hover

어느 열이 병합되든 같게 동작한다. 지원하는 rowspan 상한은 10 이며, 그보다 큰 병합은 전파되지 않는다.

중첩 병합 (묶음을 가로지르는 병합)​

rowspan 은 <tbody> 를 넘지 못한다. 배송비처럼 상품 묶음 여러 개를 가로지르는 병합이 있으면 Table.RowGroup 대신 선두 칸의 rowSpan 으로 묶음을 만든다. 선두 칸이 덮는 범위가 그 묶음이 되고, 그보다 넓은 병합이 그 위를 가로지른다.

기본 티셔츠 / 화이트 M30,000기본-금액별배송비 0원 (택배)공급사 A
[추가상품] 세탁망 / 소형
캔버스 백 / 베이지27,000
머그컵 / 320ml18,500
텀블러 / 500ml18,500
층범위덮는 칸
상품 묶음상품 + 추가상품선택 · 합계금액
배송 묶음같은 배송 조건의 상품 전체배송비
공급사공급사가 같은 상품 전체공급사

선두 칸 묶음의 지원 상한은 5행 이고, 병합 셀 상태 전파의 상한은 10행 이다. 둘 다 CSS 규칙 수와 맞바꾼 값이다.

드래그앤드롭과 병합​

rowspan 이 덮는 행은 따로 옮길 수 없다. 드래그 단위가 블록 전체로 넓어지고, 블록 가운데는 드롭 대상에서 빠진다. 범위가 겹치면 겹친 범위를 모두 합친 구간이 한 덩어리가 된다.

onRowDrop(fromId, toId, edge, moveIds) 의 moveIds 는 이번 드래그로 옮겨야 하는 행 전부다. 다중 선택과 각 선택 행의 병합 블록이 모두 들어 있으므로, 받는 쪽은 그대로 옮기면 된다. fromId 는 잡은 행이 속한 블록의 첫 행이다.

<Table.Body
  onRowDrop={(fromId, toId, edge, moveIds) =>
    setRows((prev) =>
      moveIds.length > 1 ? reorderMultipleRows(prev, moveIds, toId, edge) : reorderRows(prev, fromId, toId, edge)
    )
  }
>

vanilla ncua.Draggable 은 onDrop 의 다섯 번째 인자로 같은 목록을 준다.

new ncua.Draggable(tbody, {
  onDrop: (fromId, toId, edge, selectedIds, moveIds) => {
    // moveIds 에 다중 선택과 병합 블록이 모두 들어 있다
  },
});

HTML (CDN) 버전​

묶음 하나를 <tbody class="ncua-table__body ncua-table__row-group"> 하나로 두면 된다. 전용 스크립트는 필요 없다.

병합이 묶음을 가로지르면 <tbody> 로 묶지 않고 선두 칸의 rowspan 으로 묶는다. 전파는 똑같이 CSS 가 맡는다.

<tbody class="ncua-table__body">
  <tr class="ncua-table__row">
    <td class="ncua-table__drag-cell" rowspan="2">…</td>  <!-- 선두 칸 = 묶음 -->
    <td class="ncua-table__cell">프리미엄 노트북</td>
    <td class="ncua-table__cell" rowspan="6">전자기기</td>  <!-- 묶음 3개를 가로지른다 -->
  </tr>
  <tr class="ncua-table__row"><td class="ncua-table__cell">[추가상품] …</td></tr>
  …
</tbody>

생성기(new ncua.Table({...}))를 쓰면 mergeKeys 로 같은 결과를 얻는다. groupKey 와 함께 주면 묶음 안에서만 합쳐진다.

<div class="ncua-table ncua-table--horizontal ncua-table--hoverable">
  <table class="ncua-table__table">
    <thead class="ncua-table__header">
      <tr class="ncua-table__row">
        <th class="ncua-table__header-cell">주문상품</th>
        <th class="ncua-table__header-cell">배송비</th>
      </tr>
    </thead>

    <!-- 묶음 1 — 상위 행 + 종속 행 -->
    <tbody class="ncua-table__body ncua-table__row-group">
      <tr class="ncua-table__row ncua-table__row--selected">
        <td class="ncua-table__cell">캔버스 백 / 베이지</td>
        <td class="ncua-table__cell" rowspan="2">무료</td>
      </tr>
      <tr class="ncua-table__row">
        <td class="ncua-table__cell">네임택 각인</td>
      </tr>
    </tbody>

    <!-- 묶음 2 -->
    <tbody class="ncua-table__body ncua-table__row-group">
      <tr class="ncua-table__row">
        <td class="ncua-table__cell">머그컵 / 320ml</td>
        <td class="ncua-table__cell">2,500</td>
      </tr>
    </tbody>
  </table>
</div>

window.ncua.Table 생성기를 쓸 때는 groupKey 에 묶음 기준 필드명을 넘긴다. 값이 같은 연속된 행이 한 묶음이 된다.

new ncua.Table({
  type: 'horizontal',
  selectable: true,
  groupKey: 'orderNo',
  columns: [
    { key: 'name', label: '주문상품' },
    { key: 'delivery', label: '배송비' },
  ],
  data: [
    { orderNo: 'A-1', name: '캔버스 백 / 베이지', delivery: '무료' },
    { orderNo: 'A-1', name: '네임택 각인', delivery: '' },
    { orderNo: 'A-2', name: '머그컵 / 320ml', delivery: '2,500' },
  ],
});

Horizontal Scroll (가로 스크롤)​

horizontalScroll 을 켜면 콘텐츠가 부모 너비를 초과할 때 가로 스크롤이 발생한다. minWidth 는 미지정 시 디자인 정책 기본값 1140px 로 적용된다.

디자인 정책 (Dooray 가이드)​

  • 디자인 기준 폭 — 테이블 최소 너비 1140px (14인치 모니터 + LNB 고려). minWidth prop 기본값.
  • 트리거 — 셀별 min-width 합계 ≤ 컨테이너 폭 → 컬럼 자동 확장 / 초과 → 가로 스크롤 자동 발생.
  • 셀 최소 너비 — Table.HeaderCell.minWidth 또는 Table.ColGroup.minWidths 로 글자수 기준 지정.
  • 텍스트 처리 — 최소 너비 도달 시 말줄임 없이 줄바꿈.
  • 헤더 동작 — 세로축 sticky만 적용, 가로 스크롤 시 컬럼과 함께 가로 이동.
  • 서브영역 — Table.Footer·Table.Pagination 은 가로 스크롤 컨테이너 외부에서 항상 고정.

사용 방법​

  1. <Table draggable> — DnD 모드 활성화
  2. 헤더 첫 번째 셀에 <Table.DragHeaderCell /> 추가 (드래그 핸들 컬럼 헤더)
  3. 각 <Table.Row> 에 dragId 부여 (리스트 내 고유 ID)
  4. 각 행 첫 번째 셀에 <Table.DragCell /> 추가 (핸들 버튼 렌더)
  5. <Table.Body onRowDrop={handler}> — 드롭 이벤트 처리. 네 번째 인자 moveIds 에 옮길 행이 모두 담긴다
const [rows, setRows] = useState(initialRows);

const handleRowDrop = useCallback(
  (fromId: string, toId: string, edge: 'top' | 'bottom', moveIds: string[]) => {
    setRows((prev) => reorder(prev, moveIds, toId, edge));
  },
  []
);

<Table draggable>
  <Table.Header>
    <Table.Row>
      <Table.DragHeaderCell />
      <Table.HeaderCell>상품명</Table.HeaderCell>
    </Table.Row>
  </Table.Header>
  <Table.Body onRowDrop={handleRowDrop}>
    {rows.map((row) => (
      <Table.Row key={row.id} dragId={row.id}>
        <Table.DragCell />
        <Table.Cell>{row.name}</Table.Cell>
      </Table.Row>

  </Table.Body>
</Table>

체크사항​

  • Portal 컴포넌트 (Tooltip, Dropdown, SelectBox): 기존과 동일하게 정상 동작
  • 가로·세로 스크롤: horizontalScroll, fixedHeader 조합에서도 DnD 정상 동작. fixedHeader 모드에서는 드래그 중 자동 스크롤 지원
  • 드래그 핸들 아이콘: 체크박스 좌측에 ncua-table__drag-handle 클래스로 렌더
  • DataGrid: <DataGrid.Table draggable> 으로 동일하게 지원

필수 HTML 구조​

각 <tr> 에 data-draggable-id 속성이 필요하다. DnD 전용 BEM 클래스를 반드시 포함해야 한다.

            </button>
          </span>

초기화​

const tbody = document.getElementById('my-tbody');
const draggable = new window.ncua.Draggable(tbody, {
  onDrop(fromId, toId, edge, selectedIds) {
    // onDrop: DOM 행 이동을 콜백 내에서 직접 처리해야 한다
    const rows = Array.from(tbody.querySelectorAll('tr[data-draggable-id]'));
    const toRow = rows.find((r) => r.dataset.draggableId === toId);
    if (!toRow || selectedIds.includes(toId)) return;
    const anchor = edge === 'bottom' ? toRow.nextSibling ?? null : toRow;
    if (selectedIds.length > 1) {
      const idSet = new Set(selectedIds);
      rows.filter((r) => idSet.has(r.dataset.draggableId)).forEach((r) => tbody.insertBefore(r, anchor));
    } else {
      const fromRow = rows.find((r) => r.dataset.draggableId === fromId);
      if (fromRow) tbody.insertBefore(fromRow, anchor);
    }
  },
  onMove(direction, selectedIds) {
    // onMove: Draggable이 DOM 이동까지 내부 처리하므로 서버 동기화 등 비즈니스 로직만 작성
  },
  onSelect(selectedIds) {
    // 체크박스 선택 변경 시 처리
  },
  selectAllEl: document.getElementById('select-all'), // 전체 선택 체크박스 요소
  moveButtons: {
    top: document.getElementById('btn-move-top'),
    up: document.getElementById('btn-move-up'),
    down: document.getElementById('btn-move-down'),
    bottom: document.getElementById('btn-move-bottom'),
  },
});
onDrop vs onMove
  • onDrop — 드래그 앤 드롭 완료 시 호출. Draggable은 드래그 프리뷰만 담당하므로 실제 DOM 행 이동은 콜백 내에서 직접 처리해야 한다.
  • onMove — 이동 버튼(▲▼) 클릭 시 호출. Draggable이 DOM 행 이동까지 내부적으로 처리하므로 콜백에서는 서버 동기화 등 비즈니스 로직만 작성하면 된다.

커스텀 스크롤바​

Table 의 스크롤바는 브라우저 기본 스크롤바가 아니라 별도 DOM 요소로 구현된 커스텀 스크롤바다. 표에 마우스를 올렸을 때만 나타나며, 표 경계 안쪽에 배치된다.

React 버전은 별도 조치가 필요 없다. 아래 내용은 CDN(HTML) 버전에만 해당한다.

HTML (CDN) 버전​

window.ncua.TableScrollbar 클래스가 스크롤 상태와 커스텀 스크롤바를 연결한다.

연결 방식 — 자동(기본)·수동 모두 지원​

연결 방법은 두 가지이며, 어느 쪽을 써도 동작과 외형은 같다. 두 방식은 배타적이지 않고 한 페이지에서 섞어 쓸 수 있다. 아래 필수 HTML 구조의 세 구조 모두 자동·수동 양쪽을 지원한다.

자동 연결 (기본)수동 호출
호출불필요new window.ncua.TableScrollbar(el) 또는 TableScrollbar.init(root)
시점페이지 로드 시 1회원하는 시점
대상문서 전체의 .ncua-table넘긴 요소와 그 하위
축 지정불가 (both 고정){ axis: 'x' | 'y' | 'both' } 로 지정 가능
쓰는 경우서버가 그려 보낸 정적 표비동기 삽입, 축 한정, 특정 시점 연결

자동 연결 — 페이지 로드 시점에 문서 안의 모든 .ncua-table 을 찾아 연결한다. 아래 마크업 구조만 갖추면 별도 호출이 필요 없다.

수동 호출 — 아래 세 경우에는 직접 호출한다. 자세한 사용법은 초기화 (수동 호출) 참고.

  1. 페이지 로드 이후에 추가된 표 — 자동 연결은 로드 시 1회만 실행되므로 이후 삽입된 표는 연결되지 않는다. (→ 동적 삽입 시)
  2. 한 축만 연결하려는 경우 — axis 옵션은 수동 호출로만 지정한다.
  3. 자동 연결을 끄고 직접 통제하려는 경우 — data-ncua-scrollbar="off" 로 자동 연결에서 제외한 뒤 원하는 시점에 호출한다.
<!-- 자동 연결에서 제외하고 직접 연결 -->
<div class="ncua-table-wrapper" data-ncua-scrollbar="off">
  <div class="ncua-table ncua-table--horizontal" id="my-table">...</div>
</div>
<script>
  window.ncua.TableScrollbar.init(document.getElementById('my-table'));
</script>

필수 HTML 구조​

스크롤 컨테이너가 있어야 한다. 트랙(__scrollbar / __h-scrollbar)과 썸(__scrollbar-thumb / __h-scrollbar-thumb)은 생략 가능하며, 없으면 자동으로 생성된다.

ncua-table--horizontal 은 가로 스크롤이 아니다

이름과 달리 표 유형을 나타내는 모디파이어다. 스크롤과 무관하다.

클래스의미
ncua-table--horizontal헤더 행이 위에 오는 일반 데이터 표 (type="horizontal")
ncua-table--vertical라벨·값이 행마다 짝을 이루는 표 (type="vertical")

가로 스크롤에는 전용 모디파이어가 없다. ncua-table__h-scroll-container 구조를 갖추는 것이 곧 가로 스크롤 활성화다. ncua-table--horizontal 만 붙이고 이 컨테이너를 두지 않으면 가로 스크롤도, 커스텀 스크롤바 연결도 일어나지 않는다.

세로 스크롤은 ncua-table--fixed-header 와 ncua-table__scroll-container 가 역할을 나눠 맡는다. 둘 다 필요하다.

담당
ncua-table--fixed-header헤더 셀 position: sticky 고정, 스크롤바를 헤더 아래로 밀어 배치
ncua-table__scroll-container실제 스크롤 영역. 커스텀 스크롤바 연결 판정은 이 요소의 존재 여부로만 한다

모디파이어만 붙이고 컨테이너가 없으면 스크롤이 생기지 않아 연결 대상에서 빠지고, 컨테이너만 있고 모디파이어가 없으면 스크롤은 되지만 헤더가 함께 밀려 올라간다.

세로 스크롤 (고정 헤더):

<div class="ncua-table-wrapper">

    <div class="ncua-table__scroll-area">
      <!-- 스크롤 컨테이너 (필수) -->
      <div class="ncua-table__scroll-container" style="max-height: 240px">
        <table class="ncua-table__table">
          <thead class="ncua-table__header">...</thead>
          <tbody class="ncua-table__body">...</tbody>
        </table>
      </div>
      <!-- 트랙·썸 (선택) -->
      <div class="ncua-table__scrollbar" aria-hidden="true">
        <div class="ncua-table__scrollbar-thumb"></div>
      </div>
    </div>
  </div>

조합 모드에서는 세로 트랙을 직접 넣는다

다른 구조와 달리 이 조합에서는 세로 트랙·썸을 생략하면 안 된다.

자동 생성은 세로 트랙을 __scroll-area 안에 만들어 붙인다. 단독 세로 스크롤에서는 맞는 위치지만, 이 조합에서는 __scroll-area 가 __h-scroll-inner(최소 너비 1500px) 안에 있어 트랙이 콘텐츠와 함께 가로로 밀려난다. 화면 우측에 고정되지 않고 표 바깥으로 벗어난다.

가로 트랙·썸은 생략해도 된다 — __h-scroll-container 직계로 생성되어 위치가 맞다.

max-height 값

ncua-table__scroll-container 의 max-height 는 헤더를 포함한 높이다. 본문이 보이는 높이를 200px 로 맞추려면 헤더 높이 40px 를 더해 240px 을 지정한다.

window.ncua.Table 생성기에 maxHeight 옵션을 넘기는 경우에는 헤더 높이가 자동으로 더해진다. 즉 maxHeight: '200px' 은 본문 200px 를 의미한다.

트랙·썸을 직접 넣는 경우

트랙·썸 요소를 마크업에 직접 넣으면 그대로 사용하고, 없으면 초기화 시 자동으로 만들어 붙인다. 스크롤 동작과 외형은 두 방식이 같다.

다만 destroy() 시 처리가 다르다. 마크업에 직접 넣은 트랙은 인라인 스타일만 초기화하고 그대로 두지만, 초기화가 만들어 붙인 트랙·썸은 DOM 에서 제거한다. 트랙에 자체 스타일이나 클래스를 덧입혔다면 직접 넣어야 destroy() 후에도 보존된다.

직접 쓰면 안 되는 속성

아래 다섯 속성은 초기화가 런타임에 붙이고 떼는 예약 속성이다. 마크업에 직접 적으면 안 된다. data-ncua-scrollbar(자동 연결 제외)만 소비처가 직접 쓰는 속성이다.

속성직접 적었을 때
data-scrollbar-ready초기화가 "이미 연결된 요소"로 판단해 건너뛴다. 그 표는 커스텀·기본 스크롤바가 모두 표시되지 않으며, 콘솔에 경고가 출력된다
data-scrollbar-owner단독으로는 영향이 없지만, data-scrollbar-ready 와 함께 적으면 위 경고가 나오지 않아 원인을 찾기 어려워진다
data-scrollbar-generated영향 없음. 초기화가 만든 요소를 표시하기만 하며, destroy() 의 제거 대상은 이 속성이 아니라 초기화가 실제로 만든 요소다
data-ncua-scrollbar-fallback건너뛰는 것이 아니라, 페이지 로드 직후 기본 스크롤바가 잠깐 보였다가 사라지는 현상이 생긴다
data-dragging스크롤바가 마우스를 올리지 않아도 항상 보이는 상태가 된다

스크립트 로드 순서​

초기화 호출은 번들 로드 태그보다 반드시 뒤에 와야 한다. window.ncua 는 번들이 실행된 뒤에 만들어진다.

<body>
  <div class="ncua-table-wrapper">
    <!-- 테이블 마크업 -->
  </div>

  <!-- 1. 번들 먼저 -->
  <script src="https://fe-sdk.cdn-nhncommerce.com/@ncds/ui-admin/1.8/main.min.js"></script>

  <!-- 2. 그 다음 호출 -->
  <script>
    // window.ncua.TableScrollbar 사용 가능
  </script>
</body>

초기화 (수동 호출)​

자동 연결을 사용하지 않거나, 특정 시점에 직접 연결하려는 경우 생성자를 호출한다. 자동 연결이 이미 끝난 표를 다시 호출해도 안전하다 — 기존 인스턴스를 그대로 돌려주며 중복 연결되지 않는다.

<script src="https://fe-sdk.cdn-nhncommerce.com/@ncds/ui-admin/1.8/main.min.js"></script>
<script>
  // 1. 테이블 하나를 연결 (두 축 모두)
  const tableEl = document.getElementById('my-table');
  const scrollbar = new window.ncua.TableScrollbar(tableEl);

  // 2. 축을 지정해 연결 — 'both'(기본) | 'x' | 'y'
  const vertical = new window.ncua.TableScrollbar(tableEl, { axis: 'y' });

  // 3. 특정 영역 안의 테이블을 한 번에 연결
  const instances = window.ncua.TableScrollbar.init(document.getElementById('content'));

  // 4. 이미 연결된 인스턴스 조회
  const existing = window.ncua.TableScrollbar.getInstance(tableEl);
</script>
멤버설명
new TableScrollbar(element, options?)연결. options.axis 로 축 지정
TableScrollbar.init(root?)root 하위의 모든 .ncua-table 을 연결하고 인스턴스 배열 반환. 생략 시 문서 전체
TableScrollbar.getInstance(tableEl)연결된 인스턴스. 없으면 undefined
.axis실제로 적용된 축. 재설정 호출이 무시되었는지 확인하는 수단
.isActive연결된 축이 하나라도 있으면 true
.refresh()바깥 레이아웃을 바꾼 뒤 썸 치수·위치를 다시 계산
.destroy()연결 해제, 생성된 DOM 제거, 표식 해제
옵션은 첫 연결에만 적용된다

이미 연결된 표에 다른 axis 로 다시 호출하면 옵션이 무시되고 기존 인스턴스가 반환되며 콘솔에 경고가 출력된다. 축을 바꾸려면 destroy() 후 다시 생성한다.

const a = new window.ncua.TableScrollbar(tableEl, { axis: 'both' });
const b = new window.ncua.TableScrollbar(tableEl, { axis: 'y' }); // 경고, a 와 같은 인스턴스
a.destroy();
const c = new window.ncua.TableScrollbar(tableEl, { axis: 'y' }); // 적용됨

element 에는 .ncua-table 외에 .ncua-table-wrapper 나 .ncua-data-grid 를 넘겨도 된다. 내부에서 .ncua-table 을 찾아 연결한다. 스크롤 컨테이너가 없는 테이블을 넘기면 아무 동작도 하지 않으며, 이때 isActive 가 false 다.

잘못된 인자는 예외가 된다

element 가 null·undefined 이거나 HTMLElement 가 아니면 예외를 던진다. 호출자 오류이므로 즉시 드러낸다.

new window.ncua.TableScrollbar(null); // Error: TableScrollbar element is required
new window.ncua.TableScrollbar('#my-table'); // Error: Invalid element type provided to TableScrollbar

반면 "연결할 대상이 없는 것"은 오류가 아니다. .ncua-table 이 없거나 스크롤 컨테이너가 없는 요소를 넘기면 예외 없이 아무 동작도 하지 않는다. 자동 연결이 문서의 모든 표를 무차별로 넘기는 정상 경로이기 때문이다.

axis 에 'both'·'x'·'y' 외의 값을 넘기면 예외 대신 'both' 로 처리하고 콘솔에 경고한다. 적용된 값은 axis 로 확인할 수 있다.

동적 삽입 시​

비동기 조회 결과로 테이블을 새로 그려 넣는 경우, 삽입 직후 같은 흐름에서 초기화를 호출한다. 기존 표를 걷어내는 경우라면 걷어내기 전에 destroy() 를 먼저 호출한다.

async function reloadTable() {
  const container = document.getElementById('list-area');
  const html = await fetchTableHtml();

  // 1. 기존 표를 먼저 정리 — 노드를 걷어낸 뒤에는 정리할 수 없다
  for (const tableEl of container.querySelectorAll('.ncua-table')) {
    window.ncua.TableScrollbar.getInstance(tableEl)?.destroy();
  }

  // 2. 교체
  container.innerHTML = html;

  // 3. 삽입 직후 호출 — 서브트리 일괄 초기화
  window.ncua.TableScrollbar.init(container);
}
호출 시점

삽입과 초기화 사이에 화면이 한 번 그려지면, 그 순간 브라우저 기본 스크롤바가 잠깐 보였다가 사라진다. 삽입 직후 이어서 호출하면 이 현상이 없다.

제거 시

삽입과 제거를 반복하는 화면이라면, 테이블을 제거하기 전에 destroy() 를 호출한다. 호출하지 않으면 사라진 DOM 을 참조하는 인스턴스가 계속 쌓인다.

주입할 HTML 의 신뢰 범위

innerHTML 로 넣는 마크업은 서버에서 이스케이프를 마친 신뢰 가능한 HTML 이어야 한다. 상품명·주문자명처럼 사용자가 입력한 값이 그대로 섞이면 XSS 로 이어지므로, 값 단위로 넣을 때는 textContent 를 쓰거나 sanitize 를 거친다.

자동 연결 제외​

자동 연결 대상에서 빼려면 data-ncua-scrollbar="off" 를 붙인다. 테이블 자신이나 상위 요소 어디에 붙여도 된다.

<div class="ncua-table-wrapper" data-ncua-scrollbar="off">
  <div class="ncua-table ncua-table--horizontal ncua-table--fixed-header">
    ...
  </div>
</div>

<script>
  // 원하는 시점에 직접 연결 — 옵트아웃 속성은 직접 호출을 막지 않는다
  document.getElementById('tab-2').addEventListener('click', () => {
    window.ncua.TableScrollbar.init(document.getElementById('tab-2-panel'));
  });
</script>

직접 연결하기 전까지는 브라우저 기본 스크롤바로 동작한다.

상위 요소에 off 를 붙였더라도, 그 아래 특정 영역만 data-ncua-scrollbar="on" 으로 되살릴 수 있다. 가장 가까운 상위 값 하나만 적용된다.

설정 변경​

옵션을 바꾸려면 기존 인스턴스를 정리한 뒤 다시 만든다. 순서를 지켜야 한다.

const scrollbar = new window.ncua.TableScrollbar(tableEl); // axis: 'both'

// 세로만 연결하도록 변경
scrollbar.destroy();
const next = new window.ncua.TableScrollbar(tableEl, { axis: 'y' });
옵션을 바꿔 다시 호출하면 적용되지 않는다

이미 연결된 요소에 다른 옵션으로 생성자를 다시 호출하면, 새 옵션은 적용되지 않고 기존 인스턴스가 그대로 반환되며 콘솔에 경고가 출력된다. 화면 동작이 중단되지는 않는다. 설정을 실제로 바꾸려면 위와 같이 destroy() 를 먼저 호출해야 한다.

무시되었는지는 axis 로 확인한다. 콘솔 경고를 놓치기 쉬운 자리이므로, 설정이 반영되었는지 코드로 확인해야 한다면 이 값을 본다.

const again = new window.ncua.TableScrollbar(tableEl, { axis: 'x' });
again.axis; // 'x' 가 아니라 기존 값 — 전달한 옵션이 무시되었다는 뜻

같은 옵션으로 여러 번 호출하는 것은 안전하며, 경고 없이 기존 인스턴스를 돌려준다.

정리​

scrollbar.destroy();

테이블을 화면에서 제거하기 전에 호출한다. 호출 후에는 브라우저 기본 스크롤바로 돌아간다.

초기화가 되지 않은 테이블은 브라우저 기본 스크롤바로 동작한다. 스크롤은 정상적으로 되지만 외형이 다르다.

표시 시점표에 마우스를 올렸을 때만항상
레이아웃표 너비를 차지하지 않음일부 환경에서 표 너비를 차지

스크립트 자체가 로드되지 않으면(경로 오류·네트워크 차단 등) 스크롤바가 표시되지 않는다. 스크롤 동작 자체는 정상이다. 이 경우 브라우저 콘솔에서 번들 로드 실패 여부를 확인한다.
